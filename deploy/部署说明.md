# 部署说明

两种方式，按手上有没有服务器选一种：

| 方案 | 前提 | 成本 | 特点 |
| --- | --- | --- | --- |
| **A. Vercel 双项目** | 只要一个域名 | 免费 | 零运维；国内访问一般，有冷启动 |
| **B. Nginx + pm2** | 一台云服务器 | 几十元/月 | 稳定、快，配置多一点 |

---

# 方案 A：Vercel 双项目（无服务器）

最终形态：

```
浏览器 → music.你的域名（Vercel 托管静态站）
              ↓  /api/* 由 Vercel 服务端转发
         your-api.vercel.app（Vercel 上的 NeteaseCloudMusicApi）
              ↓
           网易云接口
```

关键点：**API 项目既不用绑域名，也不会被浏览器直接访问**。请求是 Vercel 服务器之间走的，
所以哪怕 `*.vercel.app` 在国内打不开，也不影响你的用户 —— 他们只访问 `music.你的域名`。

## A1. 先部署 API

1. 打开 <https://github.com/Binaryify/NeteaseCloudMusicApi>，右上角 **Fork**。
2. 打开 <https://vercel.com>，用 GitHub 登录 → **Add New → Project** → 选你 fork 的仓库 → **Import**。
3. 设置：
   - **Framework Preset** 选 `Other`
   - Build Command、Output Directory 全部留空
   - Root Directory 保持 `./`
4. **Deploy**，等 1–2 分钟。
5. 拿到形如 `https://netease-api-xxxx.vercel.app` 的地址后，**先验证再往下走**：

   ```bash
   curl "https://netease-api-xxxx.vercel.app/search/hot"
   ```

   返回 `{"code":200,...}` 才算成功。

### 如果第 5 步返回 404 / 500

说明仓库自带的 `vercel.json` 是 2023 年的 `builds` 旧语法，Vercel 已经不支持。用准备好的补丁：

1. GitHub 上打开你 fork 的仓库，新建文件 `api/index.js`，内容复制本仓库的
   `deploy/netease-api-vercel/api/index.js`。
2. 把根目录 `vercel.json` 的内容替换成 `deploy/netease-api-vercel/vercel.json`。
3. 回到 Vercel → **Deployments** → 最新一条 → **Redeploy**。
4. 再跑一次 curl。

## A2. 再部署播放器

1. 把本项目推到你的 GitHub 仓库。
2. 改根目录 `vercel.json`，把占位域名换成上一步的真实地址：

   ```json
   { "source": "/api/:path*", "destination": "https://netease-api-xxxx.vercel.app/:path*" }
   ```

3. Vercel → **Add New → Project** → 选本仓库 → **Import**。
   - **Framework Preset** 选 `Vite`（会自动带出 `npm run build` 和输出目录 `dist`）
4. **Deploy**，然后打开 `https://项目名.vercel.app` 搜歌试播。

## A3. 绑定域名

1. Vercel 项目 → **Settings → Domains** → 输入 `music.你的域名` → **Add**。
2. Vercel 会给出 CNAME 目标，通常是 `cname.vercel-dns.com`。
3. 回到 Spaceship → 你的域名 → **DNS Records**，新增一条：

   | Type | Name | Value | TTL |
   | --- | --- | --- | --- |
   | CNAME | `music` | `cname.vercel-dns.com` | 默认 |

4. 等几分钟到半小时，Vercel 显示 Valid Configuration 即完成，证书自动签发。

## A4. 验收

| # | 检查 | 预期 |
| --- | --- | --- |
| 1 | `https://music.你的域名/music/playList` 刷新 | 不 404 |
| 2 | `https://music.你的域名/api/search/hot` | 返回 JSON（rewrites 生效） |
| 3 | 搜歌 → 播放 | 有声音，F12 无 Mixed Content |
| 4 | F12 Network 看 `api/song/url` | 状态 200 |

## A5. 这套方案的代价

- **冷启动**：函数约 10 分钟无请求会休眠，之后第一次搜索慢 1–3 秒。
- **超时 10 秒**：免费版函数上限 10 秒，搜索偶尔会超时，表现为「获取歌曲列表失败」。
- **出口 IP 共享**：Vercel 函数出口 IP 是公共的，请求量大了可能被网易云风控，表现为拿到空列表。免费方案绕不开。
- **国内访问**：`music.你的域名` 走 Vercel 边缘节点，大陆时快时慢。主要面向国内用户的话，长期建议换方案 B。

# 方案 B：Nginx + pm2

> 目标架构：**一台服务器**上同时跑前端静态站和 Node API，Nginx 对外只暴露 80/443。
> 好处是同源，不需要处理 CORS，也不需要为 `withCredentials` 配 `Access-Control-Allow-Credentials`。

```
浏览器 ──https──> Nginx ──┬── /            → /var/www/music（dist 静态文件）
                          └── /api/*       → 127.0.0.1:3000（NeteaseCloudMusicApi）
```

---

## 0. 本地先验一遍（别跳过）

```bash
npm run build
npm run preview        # 默认 http://localhost:4173
```

`vite preview` 现在也走 `/api` 代理了（见 `vite.config.js` 的 `apiProxy`），所以这一步能直接验证**打包产物**能不能搜歌、能不能播放。

如果 preview 里就已经放不出声音，先别上传，问题在本地。

---

## 1. 服务器准备

```bash
# Node 18+（推荐 20 LTS）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs nginx
sudo npm i -g pm2
```

云厂商安全组只放行 **22 / 80 / 443**，不要放行 3000。

---

## 2. 部署 API

```bash
sudo mkdir -p /opt/netease-api /var/log/netease-api
# 把 NeteaseCloudMusicApi 整个目录上传到 /opt/netease-api（含 app.js）
cd /opt/netease-api
npm i --omit=dev

# 用仓库里的 pm2 配置启动（记得把 cwd 改成实际路径）
pm2 start /path/to/deploy/ecosystem.config.js
pm2 save && pm2 startup
```

自检：

```bash
curl -s http://127.0.0.1:3000/search/hot | head -c 100    # 应该返回 JSON
```

---

## 3. 部署前端

```bash
sudo mkdir -p /var/www/music
# 本地执行（Windows 可用 Git Bash / WinSCP）
scp -r dist/* user@your-server:/var/www/music/
```

或者用 rsync（后续更新更快）：

```bash
rsync -avz --delete dist/ user@your-server:/var/www/music/
```

---

## 4. Nginx

```bash
sudo cp deploy/nginx.conf.example /etc/nginx/conf.d/music.conf
sudo vi /etc/nginx/conf.d/music.conf     # 改 server_name / root / 证书路径
sudo nginx -t && sudo nginx -s reload
```

先只配 80 端口也能跑（把 443 那段注释掉），证书签好后再打开。

## 5. HTTPS

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d music.example.com
sudo certbot renew --dry-run      # 确认自动续期可用
```

## 6. 验收清单

| # | 检查项 | 预期 |
| --- | --- | --- |
| 1 | 直接访问 `https://域名/music/playList` 后刷新 | 不 404，页面正常 |
| 2 | `https://域名/api/search/hot` | 返回 JSON（反代通） |
| 3 | 搜歌 → 点播放 | 有声音，F12 Console **无 Mixed Content** |
| 4 | F12 Network 里音频请求 | 状态 200，协议是 `https:` |
| 5 | 切歌 / 歌词滚动 / 封面 | 正常，无红色报错 |
| 6 | 手机 4G 打开 | 能播（排除还指向 localhost） |
| 7 | `curl -I https://域名/assets/xxx.js` | `Cache-Control: public, immutable` |
| 8 | 连续快速调接口 | 超过限速返回 503（说明 limit_req 生效） |

## 7. 完全公开场景的加固

公开意味着**任何人都能访问你的 `/api`**，下面几条建议逐条落实：

1. **限流已内置**：`nginx.conf.example` 里按 IP 10 r/s、并发 10。跑起来后用 `ab` 或狂点搜索验证会触发 503。
2. **3000 端口绝不对外**：`ufw deny 3000`，云安全组也不要放行。只允许 Nginx 从 `127.0.0.1` 访问。
3. **隐藏源站 IP（可选但推荐）**：套一层 Cloudflare 免费版，域名解析走 CF，源站只放行 CF 回源 IP。这样被刷时换 IP 成本低，也能顺手开 WAF。代价是国内访问会慢一些。
4. **版权与收录**：公开站点提供完整歌曲播放有版权风险。至少做两件事：
   - 首页加一句「仅供学习交流，音乐版权归网易云及版权方所有」；
   - 加 `public/robots.txt` 禁止搜索引擎收录，避免被大规模索引：

     ```
     User-agent: *
     Disallow: /
     ```

   如果只是自己听，最省事的是直接开 Nginx basic auth（见 `nginx.conf.example` 末尾注释），一劳永逸。
5. **日志与监控**：`pm2 logs netease-api` 看接口异常；Nginx 访问日志里如果出现同一 IP 高频请求，直接 `ufw deny from <ip>`。
6. **接口随时可能变**：网易云接口调整会导致某些功能失效，页面侧已对「无版权/无地址」做了自动跳过，但接口整体不可用时只能等上游修复。

---

## 8. 日常更新流程

```bash
# 本地
npm run build
rsync -avz --delete dist/ user@your-server:/var/www/music/

# 只改了前端 → 不需要重启 API
# 改了 API 代码 → pm2 restart netease-api
```

Nginx 不用 reload（静态文件是实时读盘的），但如果你改了 `music.conf` 就要 `nginx -s reload`。

## 9. 常见故障对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面能开，点播放没反应，Console 报 Mixed Content | 音频地址是 `http://` | 已在本仓库 `getSongUrl` 里统一转 https，确认部署的是最新构建 |
| 刷新子页面 404 | 缺 SPA fallback | 检查 `try_files $uri $uri/ /index.html;` |
| 所有接口 404 | `proxy_pass` 末尾少了 `/` | 必须是 `http://127.0.0.1:3000/` |
| 接口 502 | API 没起来 / 端口不对 | `pm2 status`、`curl 127.0.0.1:3000/search/hot` |
| 搜索很慢或间歇 503 | 触发限流 | 调大 `rate` / `burst`，或排查是否被刷 |
| 图片裂开 | 图床防盗链 | 给 `<img>` 加 `referrerpolicy="no-referrer"` |
| 发版后还是旧页面 | `index.html` 被缓存 | 确认 `location = /index.html` 的 no-cache 生效 |
