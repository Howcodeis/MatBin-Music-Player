# 部署说明

两种方式，按手上有没有服务器选一种：

| 方案 | 前提 | 成本 | 特点 |
| --- | --- | --- | --- |
| **A. Spaceship 共享主机**（推荐） | 只要一个域名 | 几美元/月 | 同源、无需改代码；Node 应用走 Passenger |
| **B. Nginx + pm2** | 一台云服务器 | 几十元/月 | 稳定、快，配置多一点 |

---

# 方案 A：Spaceship 共享主机

## A0. 必须先确认的一件事

登录 Spaceship → **Hosting Manager** → 对应主机 → **Manage** → 左侧 **Advanced → Development Tools**，
看有没有 **Node.js App**（或 Node.js Selector）这个入口。

| 情况 | 说明 | 走哪条 |
| --- | --- | --- |
| 有 Node.js App | 前端和 API 能放同一台机器、同域名，最省事 | A1 |
| 没有 / 建不起来 | 共享主机只跑静态，API 需要容器 | A2（Hyperlift） |

> Spaceship 共享主机是 CloudLinux + LiteSpeed 环境。LiteSpeed 对 Passenger 式 Node 应用的支持取决于具体机型，
> 所以不要跳过这一步 —— 先看一眼，比部署到一半发现跑不起来省时间。

## A1. 同源部署（前端 + API 同一域名）

### 目录规划

```
/home/用户名/
├── public_html/          ← 放 dist 里的内容（前端）
│   └── .htaccess         ← 见 deploy/htaccess.example
└── netease-api/          ← API 源码，放在 web 根目录之外，源码不会被下载
    ├── app.js
    ├── server.js
    └── node_modules/
```

### 步骤

1. **本地构建**

   ```bash
   npm run build
   ```

2. **上传前端**：把 `dist/` 里的**内容**（不是 dist 文件夹本身）传到 `public_html/`。
   用 cPanel 的 File Manager 打包成 zip 上传再解压，比一个个传快。

3. **上传 API**：把本地 NeteaseCloudMusicApi 目录传到 `netease-api/`，
   **不要带 `node_modules`**（必须在服务器上装，本地的是 Windows 二进制）。

4. **创建 Node 应用**：cPanel → Node.js App → **Create Application**

   | 字段 | 填什么 |
   | --- | --- |
   | Node.js version | 18 或 20（选可用的最高版） |
   | Application mode | Production |
   | Application root | `netease-api` |
   | Application URL | `你的域名` + `/api` |
   | Application startup file | `app.js` |

5. **装依赖**：回到这个应用页面，点 **Run NPM Install**；
   或者复制页面上给的 `source .../bin/activate` 命令，SSH 进去执行 `npm install --omit=dev`。

6. **关掉启动时的版本检查**（重要）：编辑 `netease-api/app.js`，把

   ```js
   require('./server').serveNcmApi({ checkVersion: true })
   ```

   改成

   ```js
   require('./server').serveNcmApi({ checkVersion: false })
   ```

   它会去请求 npm registry，在共享主机的启动策略下只会拖慢甚至卡住首次响应。

7. **Restart** 这个 Node 应用。

8. **放 `.htaccess`**：把 `deploy/htaccess.example` 的内容放到 `public_html/.htaccess`。
   cPanel 会往同一文件里追加它自己的 Passenger 配置块（带 BEGIN/END 注释），
   **不要删那一段**，两者是共存的。

9. **验证**

   ```bash
   curl "https://你的域名/api/search/hot"
   ```

   返回 `{"code":200,...}` 说明 API 通了。

### 常见问题：接口 404

Passenger 默认会把 `Application URL` 里的 `/api` 前缀剥掉再转给 Node 应用。
如果没剥（Node 收到的是 `/api/song/url`，而它只认 `/song/url`），两个解法任选：

- 在 `public_html/.htaccess` 的 Passenger 配置块里加一行 `PassengerBaseURI /api`；
- 或者临时把前端 `src/utils/axiosInterceptors.js` 的 `baseURL` 改成 `/api/api/` 验证是不是这个原因。

### 常见问题：前端能开、刷新子路由 404

`.htaccess` 的 SPA 回退没生效。检查 `mod_rewrite` 段是否被 cPanel 的配置块打断，
以及 `RewriteRule . /index.html [L]` 这行是否真的存在。

## A2. API 用 Hyperlift（共享主机跑不了 Node 时）

前端仍在 `public_html`，API 交给 Spaceship 的容器托管：

1. 把 NeteaseCloudMusicApi fork 到你的 GitHub（仓库自带 `Dockerfile`，不用改）。
2. Spaceship → **Hyperlift** → 新建应用 → 关联这个仓库 → 选 Dockerfile 构建。
3. 规格选最小档即可（0.25 vCPU / 0.5 GiB 够个人站用），监听端口填 `3000`。
4. 部署完拿到一个 HTTPS 地址，绑子域名 `api.你的域名`。
5. 前端改成跨域访问：把 `src/utils/axiosInterceptors.js` 里的

   ```js
   baseURL: '/api/',
   withCredentials: true
   ```

   改成

   ```js
   baseURL: 'https://api.你的域名/',
   withCredentials: false
   ```

   > 不用动服务端的 CORS：NeteaseCloudMusicApi 会把请求的 `Origin` 原样回显到
   > `Access-Control-Allow-Origin`，所以跨域本来就能通。把 `withCredentials` 关掉只是为了
   > 避开「凭据模式不允许通配来源」这一类边界情况 —— 本项目没有登录态，不需要带 cookie。

6. `.htaccess` 里去掉和 `/api` 相关的排除规则，其余不变。

## A3. 验收

| # | 检查 | 预期 |
| --- | --- | --- |
| 1 | `https://你的域名/music/playList` 刷新 | 不 404 |
| 2 | `https://你的域名/api/search/hot` | 返回 JSON |
| 3 | 搜歌 → 播放 | 有声音，F12 无 Mixed Content |
| 4 | 手机 4G 打开 | 能播（排除指向 localhost） |
| 5 | 隔 10 分钟再打开 | 第一次稍慢（Passenger 冷启动 2–3 秒），之后正常 |

## A4. 这套方案的代价

- **冷启动**：Passenger 空闲会回收进程，隔一段时间第一次请求慢 2–3 秒。
- **CPU/内存有限**：共享主机是共享资源，搜索并发高时会明显变慢。
- **国内访问**：机房在美国，API 往返 150–250ms；音频是浏览器直连网易云 CDN，不受影响。
- **限流靠自己**：共享主机没有 Nginx 那套 `limit_req`，公开站点被刷时只能靠 cPanel 的
  「Throttle」或联系客服，这一点不如方案 B 可控。

# 方案 B：Nginx + pm2

> 目标架构：**一台服务器**上同时跑前端静态站和 Node API，Nginx 对外只暴露 80/443。
> 好处是同源，不需要处理 CORS，也不需要为 `withCredentials` 配 `Access-Control-Allow-Credentials`。

```
浏览器 ──https──> Nginx ──┬── /            → /var/www/music（dist 静态文件）
                          └── /api/*       → 127.0.0.1:3000（NeteaseCloudMusicApi）
```

## 0. 本地先验一遍（别跳过）

```bash
npm run build
npm run preview        # 默认 http://localhost:4173
```

`vite preview` 现在也走 `/api` 代理了（见 `vite.config.js` 的 `apiProxy`），所以这一步能直接验证**打包产物**能不能搜歌、能不能播放。

如果 preview 里就已经放不出声音，先别上传，问题在本地。

## 1. 服务器准备

```bash
# Node 18+（推荐 20 LTS）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs nginx
sudo npm i -g pm2
```

云厂商安全组只放行 **22 / 80 / 443**，不要放行 3000。

---

## 2. 部署 API

```bash
sudo mkdir -p /opt/netease-api /var/log/netease-api
# 把 NeteaseCloudMusicApi 整个目录上传到 /opt/netease-api（含 app.js）
cd /opt/netease-api
npm i --omit=dev

# 用仓库里的 pm2 配置启动（记得把 cwd 改成实际路径）
pm2 start /path/to/deploy/ecosystem.config.js
pm2 save && pm2 startup
```

自检：

```bash
curl -s http://127.0.0.1:3000/search/hot | head -c 100    # 应该返回 JSON
```

---

## 3. 部署前端

```bash
sudo mkdir -p /var/www/music
# 本地执行（Windows 可用 Git Bash / WinSCP）
scp -r dist/* user@your-server:/var/www/music/
```

或者用 rsync（后续更新更快）：

```bash
rsync -avz --delete dist/ user@your-server:/var/www/music/
```

## 4. Nginx

```bash
sudo cp deploy/nginx.conf.example /etc/nginx/conf.d/music.conf
sudo vi /etc/nginx/conf.d/music.conf     # 改 server_name / root / 证书路径
sudo nginx -t && sudo nginx -s reload
```

先只配 80 端口也能跑（把 443 那段注释掉），证书签好后再打开。

## 7. 完全公开场景的加固

公开意味着**任何人都能访问你的 `/api`**，下面几条建议逐条落实：

1. **限流已内置**：`nginx.conf.example` 里按 IP 10 r/s、并发 10。跑起来后用 `ab` 或狂点搜索验证会触发 503。
2. **3000 端口绝不对外**：`ufw deny 3000`，云安全组也不要放行。只允许 Nginx 从 `127.0.0.1` 访问。
3. **隐藏源站 IP（可选但推荐）**：套一层 Cloudflare 免费版，域名解析走 CF，源站只放行 CF 回源 IP。这样被刷时换 IP 成本低，也能顺手开 WAF。代价是国内访问会慢一些。
4. **版权与收录**：公开站点提供完整歌曲播放有版权风险。至少做两件事：
   - 首页加一句「仅供学习交流，音乐版权归网易云及版权方所有」；
   - 加 `public/robots.txt` 禁止搜索引擎收录，避免被大规模索引：

     ```
     User-agent: *
     Disallow: /
     ```

   如果只是自己听，最省事的是直接开 Nginx basic auth（见 `nginx.conf.example` 末尾注释），一劳永逸。
5. **日志与监控**：`pm2 logs netease-api` 看接口异常；Nginx 访问日志里如果出现同一 IP 高频请求，直接 `ufw deny from <ip>`。
6. **接口随时可能变**：网易云接口调整会导致某些功能失效，页面侧已对「无版权/无地址」做了自动跳过，但接口整体不可用时只能等上游修复。

## 8. 日常更新流程

```bash
# 本地
npm run build
rsync -avz --delete dist/ user@your-server:/var/www/music/

# 只改了前端 → 不需要重启 API
# 改了 API 代码 → pm2 restart netease-api
```

Nginx 不用 reload（静态文件是实时读盘的），但如果你改了 `music.conf` 就要 `nginx -s reload`。

## 9. 常见故障对照

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 页面能开，点播放没反应，Console 报 Mixed Content | 音频地址是 `http://` | 已在本仓库 `getSongUrl` 里统一转 https，确认部署的是最新构建 |
| 刷新子页面 404 | 缺 SPA fallback | 检查 `try_files $uri $uri/ /index.html;` |
| 所有接口 404 | `proxy_pass` 末尾少了 `/` | 必须是 `http://127.0.0.1:3000/` |
| 接口 502 | API 没起来 / 端口不对 | `pm2 status`、`curl 127.0.0.1:3000/search/hot` |
| 搜索很慢或间歇 503 | 触发限流 | 调大 `rate` / `burst`，或排查是否被刷 |
| 图片裂开 | 图床防盗链 | 给 `<img>` 加 `referrerpolicy="no-referrer"` |
| 发版后还是旧页面 | `index.html` 被缓存 | 确认 `location = /index.html` 的 no-cache 生效 |
